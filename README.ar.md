# علّول فورج ⚒️ Alloul Forge — مهارات بأسلوب Fable لـ Claude Code

**30 مهارة احترافية** تجعل أي جلسة Claude Code تعمل كنظام متعدد الوكلاء
متقدم — مع طبقة "الحدّاد" التي تجعل كلودك يطوّر مهاراته بنفسه من طريقة
عملك الفعلية.

**English: [README.md](README.md)**

مكتبة مفتوحة المصدر من **مهارات (Agent Skills)** احترافية لـ Claude Code،
تحاكي أسلوب عمل أنظمة التنسيق المتقدمة (منهجية "Fable 5"): تفكيك المشكلة
الصعبة، توزيعها على وكلاء متوازيين، التحقّق العدائي من كل نتيجة، ثم تركيب
إجابة واحدة موثوقة.

> **تنويه**: هذا مشروع مجتمعي مستقل. ليس تابعًا لشركة Anthropic ولا معتمدًا
> منها، ولا يحتوي على أي نموذج ذكاء اصطناعي. هو مجموعة أنماط هندسة أوامر
> (مهارات) تعلّم أي جلسة Claude Code أن تعمل بالطريقة التي تعمل بها الأنظمة
> متعددة الوكلاء المتقدمة.

## الفكرة الأساسية: كيف تعمل الأنظمة المتقدمة؟

قوة الأنظمة المتقدمة لا تأتي من إجابة واحدة طويلة، بل من **البنية**:

```
                 ┌──────────────┐
                 │   التفكيك    │  قسّم المهمة إلى أجزاء مستقلة
                 └──────┬───────┘
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
   ┌─────────┐     ┌─────────┐     ┌─────────┐
   │  وكيل A │     │  وكيل B │     │  وكيل C │   التوزيع: عمّال متوازون،
   └────┬────┘     └────┬────┘     └────┬────┘   كل واحد معزول عن الآخرين
        ▼               ▼               ▼
   ┌─────────┐     ┌─────────┐     ┌─────────┐
   │ مشكّك 1 │     │ مشكّك 2 │     │ مشكّك 3 │   التحقّق: فاحصون عدائيون
   └────┬────┘     └────┬────┘     └────┬────┘   يحاولون "دحض" كل نتيجة
        └───────────────┼───────────────┘
                        ▼
                 ┌──────────────┐
                 │   التركيب    │  ادمج فقط ما نجا من التحقّق
                 └──────────────┘
```

أربعة مبادئ مغروسة في كل مهارة من مهارات هذه المكتبة:

1. **فكّك قبل أن تنفّذ.** لا تتوازى المهمة إلا بقدر جودة خطتها.
2. **الاستقلالية أهم من الإجماع.** العمّال المتوازون يجب ألا يروا مخرجات
   بعضهم، وإلا اجتمعوا على نفس الخطأ.
3. **التحقّق عدائي.** لا تنجو النتيجة إلا إذا فشل مشكّك متخصص — مُوجَّه
   صراحة لدحضها — في إسقاطها.
4. **كرّر حتى الجفاف.** أعمال الاستكشاف (أخطاء، مصادر، حالات حدّية) تنتهي
   عندما تمرّ K جولات متتالية دون جديد — وليس عند عدد اعتباطي.

## لماذا تُضخّم المهارات قدرات النماذج الأصغر؟

تشغيل أكبر نموذج لكل شيء مكلف. وهناك بديل علمي صادق: **معظم الفجوة بين
نموذج جيد ونموذج متقدم في المهام الإجرائية هي فجوة منهجية، لا فجوة ذكاء
خام** — أن تعرف أنك تعيد إنتاج الخطأ قبل تصحيحه، وتقيس الأداء قبل تحسينه،
وتكتب الاختبار التقييمي قبل الـ prompt، وتتحقق عدائيًا قبل التبليغ.

ملفات المهارات تشفّر هذه المنهجية بالضبط. ملف SKILL.md لا يغيّر النموذج؛
بل يغيّر **ما يفعله** النموذج: مراحل إلزامية، شروط توقف صريحة، عقود
مخرجات، وخطوات تحقق ذاتي. عمليًا، هذا يغلق جزءًا كبيرًا من فجوة الجودة في
الأعمال المنظّمة (تصحيح، مراجعة، ترحيل، بحث) وأنت تعمل على نموذج أرخص مثل
Sonnet — بل ويجعل النماذج الأكبر نفسها أفضل، لأن المنهجية تتراكب مع القدرة.

هذا هو هدف تصميم المكتبة: **أسلوب عمل النماذج المتقدمة كملفات مفتوحة
المصدر قابلة للنقل.**

### الحدّاد (The Forge) — كلود يطوّر نفسه

الطبقة التي تميّز هذه المكتبة عن أي مجموعة مهارات ثابتة: مهارات **تصنع
وتقيس وتطوّر مهارات** من استخدامك أنت. كلودك لا يأتي بمهارات جاهزة فقط —
بل يبني مكتبة مهارات على شكل طريقة عملك الفعلية.

| المهارة | وظيفتها |
|---|---|
| [`skill-forge`](skills/skill-forge/SKILL.md) | ينقّب في جلساتك وتصحيحاتك وتاريخ git عن الأنماط المتكررة ويصوغ منها ملفات SKILL.md مخصصة لك |
| [`skill-eval`](skills/skill-eval/SKILL.md) | يثبت أن المهارة تفيد فعلًا: سيناريوهات A/B بتحكيم أعمى ← ترقية / تعديل / إحالة للتقاعد |
| [`claude-tuner`](skills/claude-tuner/SKILL.md) | يجمّع إعداد كلود شخصيًا من الأدلة: ملف CLAUDE.md مفصّل عليك، وتشكيلة مهارات، وصلاحيات، وhooks |

دورة التطوير الذاتي: `claude-tuner` يدقق ← `skill-forge` يولّد ←
`skill-eval` يثبت ← `work-hub` يتتبع الترقية ← `knowledge-loop` يحفظ
الإيقاع. والجودة مفروضة آليًا: [`tools/skill_lint.py`](tools/skill_lint.py)
يفحص صيغة وسلامة كل مهارة في CI (انظر `.github/workflows/skill-lint.yml`).

### النمو الشخصي — النظام ينمّي الإنسان، لا الكود فقط

الطبقة الأندر: مهارات تربط **الشخص نفسه** بأعماله وإنجازاته. أهداف مربوطة
بالعمل الفعلي مع كشف الانحراف، خطط تُبنى بالعد التنازلي من النتيجة مع
معايير إيقاف، سجل مُسنَد بالأدلة للمهارات التي **يكتسبها الإنسان** (مع
مراجعات استرجاع مولّدة من عقله الثاني)، وملف شخصي بموافقة صريحة يعيش في
جهازه ويجعل كل جلسة أكثر ملاءمة له.

## التثبيت

المهارات بصيغة `skills/<name>/SKILL.md` المتوافقة مع Claude Code.

**داخل مشروع واحد** (مُوصى به):

```bash
git clone https://github.com/mbt7000/alloul-forge
cp -r alloul-forge/skills/* your-project/.claude/skills/
```

**عالميًا** (متاح في كل المشاريع):

```bash
cp -r alloul-forge/skills/* ~/.claude/skills/
```

أو استخدم السكربت المساعد:

```bash
./install.sh            # يثبّت في ‎.claude/skills‎ داخل المستودع الحالي
./install.sh --global   # يثبّت في ~/.claude/skills
```

ثم في أي جلسة Claude Code:

```
/orchestrate أعد هيكلة وحدة المدفوعات لتكون idempotent
/deep-research ما أحدث المقاربات للموصلات الفائقة بدرجة حرارة الغرفة؟
/parallel-review
```

## كيف تحقق المهارات التوازي فعليًا؟

يوفّر Claude Code آليتين أصليتين تبني عليهما المهارات:

- **أداة `Agent`** — إطلاق وكلاء فرعيين؛ الاستدعاءات المتعددة المُرسلة معًا
  تعمل بشكل متزامن. المهارات توجّه النموذج لتجميع الإطلاقات المستقلة في
  دفعة واحدة.
- **أداة `Workflow`** (حيثما توفرت) — سكربت JavaScript حتمي للتنسيق مع
  `parallel()` و`pipeline()` ومخططات مخرجات منظّمة لكل وكيل.

كل مهارة تتدهور بسلاسة: إن وُجدت أداة `Agent` فقط استُخدم الوكلاء
المجمّعون؛ وإن لم توجد أي منهما نُفّذت نفس المراحل تسلسليًا في سياق واحد —
فالمهم هو **البنية** (تفكيك/تحقّق/تركيب) وهي محفوظة في كل الحالات.

## المساهمة

المساهمات مرحّب بها. المهارة الجيدة:

1. تتبع صيغة `skills/<name>/SKILL.md` مع ترويسة YAML‏ (`name`،
   `description`).
2. تشفّر نمطًا **بنيويًا** (كيف يُرتَّب الوكلاء)، لا مجرد أسلوب صياغة.
3. تنصّ صراحة على شرط التوقف — كل حلقة يجب أن تنتهي.
4. تعمل بسلاسة حتى عند غياب أدوات الوكلاء الفرعيين.
